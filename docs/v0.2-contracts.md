# D Studio v0.2 — build contracts (internal)

Goal of v0.2 (from the product owner):
1. Match Markov Studios capture: 30 fps CFR H.264 (libx264 CRF 23), native
   resolution, single display, **cursor drawn into the video**, clip set =
   `clip.mp4, events.json, frame_events.json, metadata.json, narration.json`
   (JSONL for the two event files). Allow 60 fps as an option (30 stays default).
2. Chinese + English UI everywhere a user looks (recorder bar, settings, CAD
   form, app picker, annotation viewer, installer, messages/validation).
3. **App-only mode**: user picks one application; the video stays the full
   monitor resolution (Markov is full-screen) but every pixel not belonging to
   that app's windows (notifications, chat pop-ups, other apps, taskbar,
   desktop) is painted **black** in real time, before it reaches the encoder.
   The app's own menus/dialogs/tooltips (same process) stay visible. When
   another app comes to the foreground, recording **auto-pauses** (time is cut,
   exactly like Markov's privacy masking) and resumes when the app is back.
4. Pause/continue (exists: F9 / F10), export in Markov's format even when the
   narration / task rubric are not ready yet ("export recording only").
5. One-click Windows install: `DStudio-Setup-<ver>.exe` (per-user, no admin,
   bundles Python + deps + FFmpeg) and a portable zip.

Shared modules already written (import, don't fork):
* `recorder/i18n.py` — `L(zh, en, **fmt)`, `both()`, `get_language()`,
  `set_language()`, `toggle_language()`, `on_change(cb)`. Write every
  user-facing string as `L("中文", "English")`. Code/log/console strings may stay English.
* `recorder/settings.py` — `load_settings()`, `update_settings(**kw)`, `DEFAULTS`.
* `recorder/paths.py` — `ROOT`, `is_installed()`, `data_dir()`, `ffmpeg_path()`, `ffprobe_path()`.

## 1. Recorder CLI (`recorder/recorder.py::parse_args`)
* `--source desktop | monitor:<i> | region:x,y,w,h | window:<title> | app:<exe>`
  e.g. `--source app:SLDWORKS.exe` (exe name match is case-insensitive).
* `--app-allow EXE [EXE ...]` extra exe names that stay visible in app mode
  (default list includes IME / text-input helpers: `textinputhost.exe`,
  `ctfmon.exe`, `chsime.exe`, `inputapp.exe`; plus anything passed).
* `--app-monitor N` (optional; default = monitor holding the target's largest
  visible window at start, else the primary monitor).
* `--auto-pause-other-apps / --no-auto-pause-other-apps` (default on; only
  meaningful in app mode).
* `--draw-mouse-cursor / --no-draw-mouse-cursor` (**default ON** now).
* `--backend auto | dxcam | gdi | gdigrab`. `gdi` = new pure-Python GDI
  (BitBlt) grabber feeding frames through the same pacer/pipe as dxcam.
  App mode needs a frame-in-Python backend: `auto` → dxcam if usable else
  gdi; `gdigrab` is rejected for app mode with a clear bilingual error.
* `--fps` any int 1..120 (GUI offers 30 / 60). `--ffmpeg` defaults to
  `paths.ffmpeg_path()`. `--out` defaults to `paths.data_dir()/rec-<stamp>`.

## 2. App picker / masking API (`recorder/app_mask.py`)
* `list_apps() -> list[dict]`: one entry per exe with a visible, uncloaked,
  non-minimized, titled top-level window, excluding our own process:
  `{"exe": "SLDWORKS.exe", "name": "SOLIDWORKS", "pids": [..], "titles": [..], "hwnds": [..]}`
  sorted by name. Must not raise on Windows; returns `[]` elsewhere.
* `AppMasker(target_exe, allow_exes=(), own_pid=os.getpid(), capture_rect=(x,y,w,h))`
  * `.compute() -> MaskResult` with `black_rects` (list of `(x0,y0,x1,y1)` in
    capture-local px, half-open), `target_visible: bool`,
    `foreground_is_target: bool`, `foreground_exe: str`.
  * `apply(frame, rects)` paints rects black in a numpy BGRA frame (slice
    assignment, no per-pixel Python).
* Pure geometry (`subtract_rect`, `visible_region`, `complement`) must be
  testable on macOS/Linux with fake window lists (no Windows imports at module
  import time, or guarded).

## 3. Recorder event semantics
* While paused (manual **or** auto) **no** input/window/system events are
  written; global hotkeys still work. On every resume emit a state snapshot
  (Markov opens each segment this way): `screen_config` (reason "open"),
  `active_app`, `appearance_change`, battery/power, `memory_pressure`, and a
  `mouse_move` at the current cursor position.
* Auto-pause (app mode): foreground process is neither target, allow-listed,
  nor our own process for ≥ 300 ms → emit `privacy_mask_start`
  `{trigger:"non_target_app", maskTrigger:"non_target_app", maskDetail:<exe lower>,
  appName:<friendly>, exeName:<exe>, windowTitle:"", maskedDisplay:<monitor idx>}`
  then pause. When the target is foreground again → resume, then emit
  `privacy_mask_end` (same fields). Window titles of non-target apps are
  never logged. A manual pause is never auto-resumed.
* `Recorder.snapshot()` adds `auto_paused`, `capture_mode`, `target_exe`,
  `masked_now`.

## 4. `raw/capture.json` additions (recorder writes, packager reads)
`capture_mode` (`desktop|monitor|region|window|app`), `capture_rect`
`{x,y,width,height}` (virtual-screen px shown by the video), `cursor_in_video`
(bool), `app_target` (`{exe, allow, auto_pause}` or null), `mask_stats`
(`{masked_frames, auto_pauses, auto_paused_ms}`).

## 5. Packager
* Internal `metadata.json` gains `capture_mode`, `cursor_in_video`.
  The Markov export keeps only the sample's fields (unchanged behaviour).
* Validation: app mode whose video size equals `capture_rect` counts as
  full-screen; fps ≠ 30 is a *warning* ("Markov samples are 30 fps").
* `packager.export_cad.export_recording(dataset, destination) -> str` writes
  the Markov clip set (5 files) without a task set; needs `technical_ok`;
  writes `{"summary": "", "annotations": []}` if there is no narration yet;
  refuses to overwrite; raises `ValueError` with a bilingual message.
  CLI: `python -m packager.export_cad --recording-only --dataset D --out O`.

## 6. GUI (`recorder/gui.py`, `session_form.py`, new `app_picker.py`)
中/EN switch (persisted), fps 30/60 selector, mode Full screen / App only +
"Choose app…" (uses `list_apps`), cursor checkbox, export buttons ("Export
recording" + existing CAD export), open folder, open annotator (starts the
viewer server in-process via `tools.serve.start_server`). CI hook:
`python -m recorder gui --screenshot OUT.png --lang en|zh [--expand]` renders,
saves a PNG of the bar, exits 0.

## 7. Viewer / server
`tools/serve.py`: `--data-dir` (default `paths.data_dir()`),
`start_server(port=8000, data_dir=None, open_browser=False) -> (server, thread)`;
serves `/data/<id>/…` from the data dir. Viewer UI bilingual with a toggle
(`localStorage["dstudio.lang"]`, `?lang=zh|en`, default from browser
language). If `metadata.cursor_in_video` the cursor overlay starts off.

## 8. Installer / CI
`installer/` builds on GitHub Actions `windows-latest`; `.github/workflows/`
runs unit tests (ubuntu + windows), Windows E2E recordings
(`tests_windows/`), GUI screenshots (both languages), builds Setup.exe +
portable zip, silently installs and runs the installed self-test, uploads
artifacts.

File ownership is fixed per agent; do not edit files you don't own.
